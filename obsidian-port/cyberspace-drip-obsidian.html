01

How an Obsidian theme works

Unlike VS Code's JSON, an Obsidian theme is CSS. You override Obsidian's built-in CSS custom properties — the same variables the default theme uses — so the app repaints. Four moving parts:

1

theme.css the whole theme

One stylesheet. Define color variables under .theme-dark (and optionally .theme-light), plus any selector overrides. This is where the entire palette lives.

2

manifest.json metadata

Name, version, author, minAppVersion. Lives beside theme.css in .obsidian/themes/Cyberspace Purple Drip/.

3

CSS variables the contract

Obsidian exposes ~hundreds of --background-*, --text-*, --code-*, --h1-color… vars. Set them and the UI follows. No need to fight selectors for most things.

4

Style Settings block user controls

A /* @settings */ YAML comment turns chosen variables into a live settings UI (color pickers, toggles, sliders) via the Style Settings community plugin.

02

Core palette → Obsidian variables

The dark workbench colors mapped to Obsidian's foundation. Click any swatch to copy. The accent is given as hsl-split so Style Settings can drive Obsidian's whole accent system.

03

Markdown & code highlighting

This is where the syntax rainbow earns its keep — headings, code fences, links, bold/italic and callouts reuse the exact token colors from the VS Code theme.

04

Style Settings integration

Style Settings reads a YAML block embedded in a CSS comment and builds a settings panel. We expose the accent, backgrounds, heading colors, code-token colors, and a few toggles. Exact shape:

/* @settings

name: Cyberspace Purple Drip
id: cyberspace-purple-drip
settings:
    -
        id: cpd-accent-heading
        title: Accent
        type: heading
        level: 2
    -
        id: accent       # drives --accent-h / -s / -l
        title: Accent color
        type: variable-color
        format: hsl-split
        default: '#c895df'
    -
        id: cpd-bg
        title: Editor background
        type: variable-color
        format: hex
        opacity: false
        default: '#3b205a'
    -
        id: cpd-rainbow-headings
        title: Rainbow headings
        description: Color h1–h6 across the drip palette
        type: class-toggle
        default: true

*/

🎨 Accent

hsl-split on --accent → Obsidian rebuilds --interactive-accent, link colors and more from your one pick.

🌈 Toggles

class-toggle for rainbow headings, italic comments, and a "drippy" tab/active glow — body classes the CSS keys off.

🧩 Token colors

Each --code-* token exposed as a variable-color so power users can retune the syntax rainbow live.

Build checklist (the handoff)

What the build Claude must produce. Feed it BUILD-PROMPT.md + this page; these are the acceptance criteria.

01
manifest.json

name "Cyberspace Purple Drip", author "DripHacker", a version, minAppVersion, and a one-line description noting it's a port of zzAIMoo's Space Purple.

02
theme.css with the full dark palette

All core variables from §2 set under .theme-dark; markdown/code vars from §3. Dark-first (a Light pass is optional/secondary).

03
A working /* @settings */ block

Accent (hsl-split), key backgrounds, heading colors, every --code-* token, plus toggles — all with correct defaults from this map.

04
Code-block syntax coverage

Map the rainbow to both reading-view Prism (--code-*) and editor CodeMirror (.cm-*) so fenced code looks identical to VS Code.

README + install note
